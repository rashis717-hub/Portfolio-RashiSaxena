# Impeccable usage rules

1. /DESIGN.md is the single source of truth for tokens and style. Impeccable advises; DESIGN.md decides. If an Impeccable suggestion conflicts with DESIGN.md (new accent colour, different font, added shadow, extra decorative effects), do not apply it; report the conflict and the alternative that stays within DESIGN.md.
2. For any new page, section or component: run `/impeccable shape <target>` first and show me the plan before coding.
3. After building: run `/impeccable critique <target>` and `/impeccable audit <target>`, fix every P0 and P1 finding, list P2 and P3 for me, and re-run to confirm.
4. Before I commit a finished page: run `/impeccable polish <target>`.
5. Before deployment: run `/impeccable harden` and `/impeccable optimize` across the site.
6. Only suggest or run commands that exist in the installed version; if unsure, run `/impeccable` to list them.
7. Never let Impeccable add a photograph, stock illustration, gradient decoration, second accent colour, or invented content.
